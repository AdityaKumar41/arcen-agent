# Tools

Tools are registered through `tools/registry.py`, discovered by `model_tools.py`, and exposed through toolsets in `toolsets.py`.

## Default path for new tools

For local or custom tools, prefer a plugin under `~/.arcen/plugins/<name>` instead of editing Arcen core. Plugins can register tools through `ctx.register_tool(...)` and can be enabled or disabled without changing built-in toolsets.

Use core tools only when the tool should ship in the base system.

## Core tool checklist

1. Create `tools/your_tool.py`.
2. Register the schema and handler with `registry.register(...)`.
3. Return a JSON string from the handler.
4. Add the tool name to `_ARCEN_CORE_TOOLS` or another toolset in `toolsets.py`.
5. Use `get_arcen_home()` for state and `display_arcen_home()` for path text in schemas.

```python
from tools.registry import registry

registry.register(
    name="example_tool",
    toolset="example",
    schema={
        "name": "example_tool",
        "description": "Do one specific thing.",
        "parameters": {"type": "object", "properties": {}},
    },
    handler=lambda args, **kw: '{"success": true}',
)
```

<Callout type="warning" title="Toolset exposure is required">
  Auto-discovery imports the module and registers the schema. The tool is exposed to agents only when its name appears in a toolset.
</Callout>

## Agent-level tools

Some tools are intercepted by `run_agent.py` before normal function dispatch. `tools/todo_tool.py` is the reference pattern for agent-level behavior.
