# Messaging gateway

The gateway lets you talk to Arcen from messaging platforms while the agent runs on a server, workstation, or cloud machine.

## Supported surfaces

The repository includes adapters for Telegram, Discord, Slack, WhatsApp, Signal, Matrix, Mattermost-style flows, Email, SMS, DingTalk, WeCom, Weixin, Feishu, QQ Bot, BlueBubbles, Yuanbao, webhook, API server, and Home Assistant.

Gateway platform code lives in `gateway/platforms`.

## Start setup

```bash
arcen gateway setup
arcen gateway start
```

Run logs while testing:

```bash
arcen logs --follow --level info
```

## Working directory

Messaging sessions use `terminal.cwd` from `~/.arcen/config.yaml`:

```yaml
terminal:
  cwd: /srv/arcen/workspace
```

The gateway bridges this into child tool environments as `TERMINAL_CWD`.

<Callout type="warning" title="MESSAGING_CWD is removed">
  Do not configure `MESSAGING_CWD` in `.env`. Use `terminal.cwd` in `config.yaml`.
</Callout>

## Gateway slash commands

The gateway shares canonical slash command names through `arcen_cli/commands.py`. Some commands are CLI-only by default but can be exposed in the gateway with a `gateway_config_gate`.

## Multiple gateways

You can run multiple gateway processes, one per profile. Only one process should own kanban dispatch:

```yaml
kanban:
  dispatch_in_gateway: false
```

Keep `dispatch_in_gateway: true` only on the profile that owns dispatching.
